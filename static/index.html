Authenticated HTTP-to-SMTP email relay.

A lightweight, multi-tenant FastAPI microservice for sending transactional email from any application over SMTP—with SHA-256 hashed API keys, optional HMAC-SHA256 request signing, and per-app rate limits.

Endpoint
POST /send
Authentication
X-API-Key + HMAC
Tenant Config
TENANT_<APP>
Limits
5 MB · 50 recipients

What Mailbridge Does

Instead of embedding SMTP credentials and MIME boilerplate into every backend or serverless function, your apps send a single authenticated JSON request to POST /send. Mailbridge validates the caller, enforces limits, and delivers the email over SMTP.

Request Lifecycle

01
Rate Limit
Sliding-window check per client IP and per app_id.
02
Key Auth
SHA-256 hash of X-API-Key compared in constant time.
03
HMAC & Replay
Optional X-Signature, timestamp window, and nonce check.
04
SMTP Delivery
Builds MIME message and sends asynchronously via STARTTLS or SSL.

Security Highlights

  • Zero plaintext API keys on server: Only SHA-256 key_hash values are stored in environment variables.
  • Per-app isolation: Each app has its own sender identity (from_name, from_email), rate limit, optional recipient domain allowlist, and optional dedicated SMTP credentials.
  • Abuse guards: Enforces max body size (5 MB), max recipients (50), max attachments (5 × 3 MB), header-injection sanitization, and blocks executable attachments (.exe, .js, .ps1, etc.).
  • Sanitized errors: Internal SMTP errors are logged server-side and returned as a generic 502 Email delivery failed.

2. Call POST /send

Send a JSON payload with X-API-Key and X-App-Id. If your tenant has a signing_secret, also include X-Timestamp, X-Nonce, and X-Signature.

Request Headers

Header Required Description
X-API-Key Yes Raw API key (er_...) issued for the calling app.
X-App-Id Recommended Tenant identifier (e.g. my-app) for direct lookup.
X-Timestamp If HMAC enabled Unix epoch seconds as a string (default tolerance: ±60s).
X-Nonce If HMAC enabled Unique UUID per request (replay protection).
X-Signature If HMAC enabled Hex HMAC-SHA256(signing_secret, f"{timestamp}.{nonce}.{raw_body}").

Example Request (cURL)

bash 
curl -X POST https://mailbridge-akdey.vercel.app/send \
  -H "Content-Type: application/json" \
  -H "X-App-Id: my-app" \
  -H "X-API-Key: er_your_raw_api_key" \
  -d '{
    "to_email": "user@example.com",
    "subject": "Welcome",
    "html_content": "<h1>Hello</h1><p>Sent via Mailbridge.</p>",
    "text_content": "Hello\nSent via Mailbridge."
  }'

Success Response (200 OK)

json 
{
  "status": "sent",
  "request_id": "a1b2c3d4-...",
  "app_id": "my-app",
  "recipients": ["user@example.com"]
}

# Mailbridge Email Integration

Use this skill when adding transactional email sending to an application via Mailbridge (`https://mailbridge-akdey.vercel.app`).

## 1. Environment Variables
- `MAILBRIDGE_URL`: Base URL of Mailbridge (`https://mailbridge-akdey.vercel.app`)
- `MAILBRIDGE_APP_ID`: Tenant identifier sent in `X-App-Id` (e.g., `my-app`)
- `MAILBRIDGE_API_KEY`: Secret API key sent in `X-API-Key` (`er_...`)
- `MAILBRIDGE_SIGNING_SECRET`: Optional 64-char hex HMAC-SHA256 secret

## 2. API Contract (`POST {MAILBRIDGE_URL}/send`)
- **Headers:** `Content-Type: application/json`, `X-API-Key`, `X-App-Id`, plus `X-Timestamp`, `X-Nonce`, `X-Signature` (`HMAC-SHA256(secret, f"{ts}.{nonce}.{raw_json_body}")`) when `MAILBRIDGE_SIGNING_SECRET` is set.
- **JSON Body:** `to_email` (string or array), `subject`, `html_content` and/or `text_content`, optional `reply_to`, `cc`, `bcc`, `attachments`.
- **Response (`200 OK`):** `{ "status": "sent", "request_id": "...", "app_id": "...", "recipients": [...] }`

## 3. Requirements
1. Create a reusable email client module matching the project's conventions.
2. Compute `X-Signature` over the exact raw JSON bytes sent in the HTTP body.
3. Document `MAILBRIDGE_*` in `.env.example` and never log secrets.
4. Add unit tests mocking the HTTP call.
