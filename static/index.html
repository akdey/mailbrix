Authenticated HTTP-to-SMTP email relay.

A lightweight, multi-tenant FastAPI microservice for sending transactional email from any application over SMTP—with SHA-256 hashed API keys, optional HMAC-SHA256 request signing, and per-app rate limits.

Endpoint
POST /send
Authentication
X-API-Key + HMAC
Tenant Config
TENANT_<APP>
Limits
5 MB · 50 recipients

What Mailbridge Does

Instead of embedding SMTP credentials and MIME boilerplate into every backend or serverless function, your apps send a single authenticated JSON request to POST /send. Mailbridge validates the caller, enforces limits, and delivers the email over SMTP.

Request Lifecycle

01
Rate Limit
Sliding-window check per client IP and per app_id.
02
Key Auth
SHA-256 hash of X-API-Key compared in constant time.
03
HMAC & Replay
Optional X-Signature, timestamp window, and nonce check.
04
SMTP Delivery
Builds MIME message and sends asynchronously via STARTTLS or SSL.

Security Highlights

  • Zero plaintext API keys on server: Only SHA-256 key_hash values are stored in environment variables.
  • Per-app isolation: Each app has its own sender identity (from_name, from_email), rate limit, optional recipient domain allowlist, and optional dedicated SMTP credentials.
  • Abuse guards: Enforces max body size (5 MB), max recipients (50), max attachments (5 × 3 MB), header-injection sanitization, and blocks executable attachments (.exe, .js, .ps1, etc.).
  • Sanitized errors: Internal SMTP errors are logged server-side and returned as a generic 502 Email delivery failed.

1. Register a Calling App (e.g. my-app)

Each calling app gets its own TENANT_<APP> environment variable on Mailbridge. Adding a new app in Vercel never overwrites existing apps.

Step 1: Generate Credentials (In-Browser)

Runs 100% locally in your browser using Web Crypto (crypto.getRandomValues + SHA-256). Nothing is sent to the server. Every click generates a brand-new random key and hash.

2. Call POST /send

Send a JSON payload with X-API-Key and X-App-Id. If your tenant has a signing_secret, also include X-Timestamp, X-Nonce, and X-Signature.

Request Headers

Header Required Description
X-API-Key Yes Raw API key (er_...) issued for the calling app.
X-App-Id Recommended Tenant identifier (e.g. my-app) for direct lookup.
X-Timestamp If HMAC enabled Unix epoch seconds as a string (default tolerance: ±60s).
X-Nonce If HMAC enabled Unique UUID per request (replay protection).
X-Signature If HMAC enabled Hex HMAC-SHA256(signing_secret, f"{timestamp}.{nonce}.{raw_body}").

Example Request (cURL)

bash 
curl -X POST https://mailbridge-akdey.vercel.app/send \
  -H "Content-Type: application/json" \
  -H "X-App-Id: my-app" \
  -H "X-API-Key: er_your_raw_api_key" \
  -d '{
    "to_email": "user@example.com",
    "subject": "Welcome",
    "html_content": "<h1>Hello</h1><p>Sent via Mailbridge.</p>",
    "text_content": "Hello\nSent via Mailbridge."
  }'

Success Response (200 OK)

json 
{
  "status": "sent",
  "request_id": "a1b2c3d4-...",
  "app_id": "my-app",
  "recipients": ["user@example.com"]
}

3. Calling App Env & Integration Prompt

Add these environment variables to your calling app (such as my-app), or paste the prompt below into your AI coding assistant to wire up the client automatically.

Calling App .env

env 
MAILBRIDGE_URL=https://mailbridge-akdey.vercel.app
MAILBRIDGE_APP_ID=my-app
MAILBRIDGE_API_KEY=er_replace_with_raw_api_key
MAILBRIDGE_SIGNING_SECRET=replace_with_64_char_hex_signing_secret

AI Integration Prompt

prompt 
Integrate email sending into this application using our Mailbridge HTTP-to-SMTP relay service.

Configuration (read from environment variables, never hardcode):
- MAILBRIDGE_URL: Base URL of the Mailbridge service (https://mailbridge-akdey.vercel.app)
- MAILBRIDGE_APP_ID: App identifier for the X-App-Id header (e.g., my-app)
- MAILBRIDGE_API_KEY: Secret API key for the X-API-Key header
- MAILBRIDGE_SIGNING_SECRET: Optional HMAC-SHA256 signing secret. When set, sign every POST /send request with:
  - X-Timestamp: current Unix epoch seconds as a string
  - X-Nonce: unique UUID per request
  - X-Signature: hex digest of HMAC-SHA256(MAILBRIDGE_SIGNING_SECRET, f"{timestamp}.{nonce}.{raw_json_body}")

API Contract (POST {MAILBRIDGE_URL}/send):
- Headers:
  - Content-Type: application/json
  - X-API-Key: <MAILBRIDGE_API_KEY>
  - X-App-Id: <MAILBRIDGE_APP_ID> (if set)
  - X-Timestamp, X-Nonce, X-Signature (if MAILBRIDGE_SIGNING_SECRET is set)
- JSON Body:
  - to_email (required): string or array of email strings
  - subject (required): string (1-998 chars)
  - html_content (optional): HTML body string
  - text_content (optional): plain-text body string (at least one of html_content or text_content is required)
  - reply_to, cc, bcc, attachments (optional)
- Success Response (200 OK):
  { "status": "sent", "request_id": "...", "app_id": "...", "recipients": [...] }

Requirements:
1. Create a reusable email client/helper module following this project's conventions.
2. Compute the HMAC signature over the exact raw JSON bytes sent in the HTTP request body.
3. Add the MAILBRIDGE_* variables to .env.example.
4. Handle non-200 responses and timeouts cleanly without logging secrets.
5. Add unit tests mocking the HTTP call.
