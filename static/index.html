Mailbrix

Authenticated HTTP-to-SMTP email relay.

Send transactional email from any app via a single POST /send endpoint—with hashed API keys, optional HMAC signing, and per-app rate limits.

Endpoint
POST /send
Auth
X-API-Key + HMAC
Tenants
TENANT_<APP>
Limits
5 MB · 50 recipients

Request Lifecycle

01
Rate Limit
Sliding window per IP and app_id.
02
Key Auth
SHA-256 X-API-Key constant-time check.
03
HMAC & Replay
Optional signature, timestamp, and nonce check.
04
SMTP Delivery
Async MIME delivery via STARTTLS / SSL.

Security

  • Hashed keys: Only SHA-256 key_hash values are stored on the server.
  • Per-app isolation: Dedicated from_name, from_email, rate limit, and optional SMTP/domain allowlist.
  • Abuse guards: 5 MB max body, 50 recipients, 5 attachments (≤ 3 MB each), no executable extensions.

POST /send

Header Required Description
X-API-Key Yes Raw API key (er_...).
X-App-Id Recommended Tenant ID (e.g. my-app).
X-Timestamp If HMAC Unix epoch seconds (±60s).
X-Nonce If HMAC Unique UUID per request.
X-Signature If HMAC HMAC-SHA256(secret, "{ts}.{nonce}.{raw_body}")

# Mailbrix Email Integration

Use this skill when adding transactional email sending to an application via Mailbrix (`https://mailbrix-akdey.vercel.app`).

## 1. Environment Variables
- `MAILBRIX_URL`: Base URL of Mailbrix (`https://mailbrix-akdey.vercel.app`)
- `MAILBRIX_APP_ID`: Tenant identifier sent in `X-App-Id` (e.g., `my-app`)
- `MAILBRIX_API_KEY`: Secret API key sent in `X-API-Key` (`er_...`)
- `MAILBRIX_SIGNING_SECRET`: Optional 64-char hex HMAC-SHA256 secret

## 2. API Contract (`POST {MAILBRIX_URL}/send`)
- **Headers:** `Content-Type: application/json`, `X-API-Key`, `X-App-Id`, plus `X-Timestamp`, `X-Nonce`, `X-Signature` (`HMAC-SHA256(secret, f"{ts}.{nonce}.{raw_json_body}")`) when `MAILBRIX_SIGNING_SECRET` is set.
- **JSON Body:** `to_email` (string or array), `subject`, `html_content` and/or `text_content`, optional `reply_to`, `cc`, `bcc`, `attachments`.
- **Response (`200 OK`):** `{ "status": "sent", "request_id": "...", "app_id": "...", "recipients": [...] }`

## 3. Requirements
1. Create a reusable email client module matching the project's conventions.
2. Compute `X-Signature` over the exact raw JSON bytes sent in the HTTP body.
3. Document `MAILBRIX_*` in `.env.example` and never log secrets.
4. Add unit tests mocking the HTTP call.
